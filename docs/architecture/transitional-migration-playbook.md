# Transitional Migration Playbook (90-Day Program)

Date: 2026-03-05  
Scope: AssistSupport rewrite/refactor program with compatibility-first delivery.

## Guardrails

1. No user-visible behavior change without a matching golden journey assertion.
2. Public command names remain stable as `v1` facades until deprecation criteria is met.
3. Every structural refactor must ship behind one of:
   - compatibility facade,
   - reversible adapter,
   - feature flag.
4. Contract fixture drift is blocking unless intentional and reviewed.
5. Command lifecycle policy map and lock-await policy are blocking backend gates.

## Transitional Architecture Pattern

1. Introduce new module boundary behind existing command/function entrypoint.
2. Keep legacy and new implementations co-existing during migration.
3. Route through explicit adapters while parity tests run in CI.
4. Remove legacy branch only after two release cycles with zero regressions.

## Golden Journeys (Blocking)

1. Draft generation and follow-up handoff continuity.
2. Settings/policy visibility and deployment preflight diagnostics.

Location: `tests/ui/golden-journeys.spec.ts`

## Contract Gates (Blocking)

1. Tauri command DTO fixtures:
   - `contracts/tauri/v1/*`
   - test: `src-tauri/tests/command_contract_fixtures.rs`
2. Search API envelope fixtures:
   - `contracts/search-api/v1/*`
   - test: `search-api/tests/test_contract_fixtures.py`

## Release Cadence (1-2 Engineers)

1. Branch lifespan target: 1-2 days.
2. Weekly architecture checkpoint:
   - unresolved transitional adapters,
   - coupling hotspots,
   - lock policy exceptions.
3. Fortnightly release checkpoint:
   - contract pass rate,
   - golden journey pass rate,
   - DORA/scorecard trend.
